# Revisión SRE / Observabilidad / Operación — SmartBancs App

Revisor: SRE/Observabilidad. Alcance: `backend/src/common/**`, módulos `simulation`, `outbox`, `rabbitmq` (y `transactions`/`recommendations` por la traza), `ai-service/*.py`, `docker-compose.yml`, `docker/prometheus`, `docker/grafana`, `backend/sql/00-observability.sql`, `docs/DOCUMENTO_TECNICO.md` §4–6.

Qué se ejecutó para verificar:
- `npx tsc --noEmit` en backend: compila sin errores.
- Se compilaron `logger.service.ts` y `metrics.service.ts` y se ejecutaron. Así se vio el formato real de los logs y la cardinalidad de `http_requests_total`.
- Se llamó a `consumer.process_transaction_event` con el backend caído. El mensaje se confirma (`ACK`) y se pierde.
- Se levantó un PostgreSQL 16 temporal y se reprodujo una espera por `SELECT ... FOR UPDATE`. La consulta de `pg_locks` de `db-diagnostics` no muestra la espera.

## Lo que está bien

- El Transactional Outbox es real: el `INSERT` va en la misma transacción que el débito, el relay usa `FOR UPDATE SKIP LOCKED`, lleva el conteo de `attempts`/`last_error` y el gauge del backlog `smartbancs_outbox_pending_events`.
- Los errores de BD se clasifican por SQLSTATE (no por texto), con `lock_timeout`/`statement_timeout` por transacción (`SET LOCAL`), reintento solo para 40P01/40001 con jitter y 503 para contención.
- PostgreSQL arranca con `pg_stat_statements`, `log_lock_waits`, `deadlock_timeout=1s` y `log_min_duration_statement=500`. `00-observability.sql` trae la consulta correcta de `pg_blocking_pids`.
- El target de Prometheus es correcto (`backend:4000/metrics`, sin prefijo global). Todas las métricas que cita §4.1 existen en `metrics.service.ts` con los labels documentados. El dashboard consulta métricas que existen.
- El correlation ID se genera en el middleware, se persiste en `transactions` y `outbox_events` y viaja en el body y en `properties.correlationId` de AMQP.
- El consumidor de recomendaciones es idempotente (índice único parcial en `ai_recommendations.transaction_id` + comprobación previa).
- La API key de Gemini va en el header `x-goog-api-key` (no en la URL), la llamada tiene timeout de 10 s y hay fallback heurístico. No hay secretos reales versionados.
